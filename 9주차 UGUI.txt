1. UGUI 개요

UGUI 시스템: 유니티의 공식 UI 시스템. 해당 시스템 존재 전에는 레거시 UI 시스템이 존재. (업데이트문에서 매 프레임마다 UI를 그리고 지우고를 코드 통해 제어)

레거시의 문제: 코드를 통해 UI를 생성하고 없애기 때문에 플레이 버튼을 눌러 테스트하기 전까지 UI가 어떻게 그려질지 예상 불가. 

>>유니티 UI 시스템: UI 요소를 게임 오브젝트나 컴포넌트로서 편집하게 해줌.. (플레이어에 리기드바디 붙이듯 유니티 UI시스템을 인스펙터에서 편집 가능)

UGUI 이전에 있었던 NGUI와 UGUI 중 어떤 것을 선택해야 하는가? 
ㄴNGUI: 유니티 에셋스토어에 판매중인 서드파티 UI 플러그인. (오피셜 플러그인이 아니라 유니티 최신 버전에도 업데이트 되지 않음.)

유니티의 UI 시스템으로 안드로이드나 iOS의 네이티브 앱 스타일 UI를 만들 수 있느냐?
ㄴ이미테이션은 가능. UGUI는 기본적으로 게임 오브젝트이기 때문에 모바일 API에 직접 접근하는 것은 불가능. 

2. 캔버스

캔버스: 모든 UI 게임 오브젝트들이 들어가 있는 스크린.  UI 게임 오브젝트들을 만들면 자동으로 같이 생김. 3D 게임 세상의 좌표계가 아니라 유저의 게임 화면에 1대1 대응. >>일반 큐브 오브젝트에 비해 크기가 크다. 
	캔버스의 1px 길이는 유니티 세상의 1m에 대응. 

이벤트 시스템: UI 게임 오브젝트들이 터치, 클릭, 개발자가 직접 만든 이벤트를 감지할 수 있도록 함. 자동으로 동작. 

캔버스: 모든 UI 게임 오브젝트를 위한 스크린 좌표기 제공. 캔버스 자체가 UI 오브젝트들이 배치되기 위한 프레임 제공. 
	UI 오브젝트를 캔버스의 자식에서 제외하면 보이지 않게 됨. 
	게임 화면의 해상도를 바꾸면 캔버스의 크기도 달라짐(플레이어의 화면에 대응)

캔버스의 3가지 랜덤 모드
-스크린 스페이스 오버레이
	ㄴ UI 요소들이 스크린 상에만 존재하고 모든 3D 오브젝트들이 그려진 다음 마지막으로 UI 요소들을 덮어쓰는 방식으로 그린다. 
-스크린 스페이스 카메라
	ㄴ3D 좌표상에서 위치를 가진다. 캔버스의 렌더 카메라를 지정하고 해당 카메라 기준으로 얼마만큼 떨어질지 plane distance를 지정하여 해당 위치에 UI 요소를 배치한다. 
		원래 좌표계와 상관없이 동작하던 캔버스가 좌표를 가지게 됨. 카메라를 움직이면 캔버스도 같이 움직인다. 
		카메라와 캔버스 사이에 3D 오브젝트가 배치될 수 있다. 
		ex) 파티클 효과를 UI와 카메라 사이에 배치>> UI 요소 위에 파티클 효과 표시 가능. 
-월드 스페이스
	ㄴ캔버스 자체가 3D 상에서 좌표와 회전을 모두 가진다. (아예 3D 오브젝트처럼 취급. )
		캔버스 자체를 마음대로 움직일 수 있고 회전할 수 있음. 증강현실 UI 구현할 때 사용 .(바닥이나 물건 위에 UI 표시)
		어떤 게임 오브젝트의 자식으로 넣어서 해당 게임 오브젝트가 움직일 때 같이 움직일 수 있음. 

보통은 스크린 스페이스 오버레이를 많이 사용/파티클 효과나 3D 오브젝트를 UI와 카메라 사이에 표시하고 싶으면 스크린 스페이스 카메라/UI 요소를 증강현실로 표현하고 싶으면 월드 스페이스.

캔버스는 UI 게임 오브젝트들에게 좌표계를 제공하기 때문에 모든 UI 게임 오브젝트들은 무조건 캔버스의 자식으로 있어야 한다. 

3. RectTransform+앵커,피벗,포지션

-앵커 피벗 포지션(Anchor PIvot Position): UGUI에서 UI 요소를 배치할 때 필요.
ㄴ일반적인 UI 디자인 프로그램에서도 사용되는 개념. 

앵커: UI 요소들의 원점의 위치(0,0)가 어디에서 시작되는지 결정. 
피벗: UI 요소 내부에 UI 요소를 배치할 때 필요한 핀 포인트(기준점)를 결정. 
포지션: 앵커와 피벗 기준으로 결정한 좌표. 

어떤 UI 요소의 앵커를 결정하려면 해당 요소를 포함하는 프레임에 대해 봐야 한다. 
UI 요소 입장에서 자신을 포함하는 프레임에 대한 앵커값은 좌측 하단이 (0,0), 우측 상단이 (1,1), 좌측 상단이 (0,1), 우측 하단이 (1,0)
어떤 UI 요소의 앵커값을 (0.5, 0.5) 로 설정하고 위치를 (0,0)으로 설정하면 UI 요소는 정중앙에 위치하게 됨. 
				(0,0)으로 설정하고 위치를  (0,0)으로 설정하면 UI 요소는 좌측 하단에 위치하게 됨. 

어떤 UI 요소의 앵커값을 (0.5, 0.5) 로 설정하고 위치를 (0,0)으로 설정했을 때 
피벗: UI 요소 내부의 기준점. UI 요소의 기본 피벗값은 (0.5,0.5) 이므로 기준점은 자기 자신의 정중앙. 자기 자신을 기준으로 함.
	자기 자신의 좌측 하단이 (0,0), 우측 상단이 (1,1).  자기 자신 안에 있는 무게중심으로 피벗이 바뀌면 요소가 배치되는 위치도 조금씩 바뀜. 

포지션: 앵커와 피벗에 의해 최종적으로 결정되는 좌표. 포지션이 같아도 앵커와 피벗이 다르면 전혀 다른 곳에 배치될 수 있다. 

-RectTransform 이란? Rectangle Transform의 약자. 모든 UI들이 가지고 있음. UI 요소들은 3차원이 아니라 사각형 판 위에서 배치됨. 
	x,y,z값 뿐만 아니라 width, height, anchor와 pivot 값을 가진다. 
	앵커 값에는 min, max값이 나뉘어져 있는데 min==max일 때와 아닐 때의 동작이 다르다. 
	min, max가 다를 경우: 상대값 모드로 동작(min, max의 좌표값을 좌측 하단, 우측 상단의 두 점으로 가지는 직사각형 UI 영역이 화면 크기가 조정됨에 따라 함께 크기가 조정됨)
					이때 left, right, top, bottom 값은 padding(안쪽 또는 바깥쪽으로 얼마나 밀려들어가는지/나가는지) 를 결정.  픽셀 단위임. 
					min을 (0,0), max를 (1,1)로 지정한 후 패딩 값을 전부 0으로 지정하면 UI 이미지가 화면을 가득 채우게 됨. 
					앵커값의 x값은 같게, y값은 다르게 하면>> 가로 방향에 대해서는 상대값 모드, 세로 방향에 대해서는 절대값 모드가 되어 세로 방향은 값을 직접 지정 가능하고 가로방향은 상대적으로 길이 조정됨. 

	같을 경우: 절대값 모드로 동작

앵커 프리셋: 가장 자주 사용되는 앵커, 피벗, 포지션을 모아놓아 제공. 앵커 프리셋을 사용할 때 기본 값으로는 앵커의 위치만 바꾸면 됨. 
		alt 키와 함께 앵커 위치를 누르면 앵커 값에 따라 오브젝트 위치가 변한다. shift 키와 함께 누르면 피벗 포인트도 같이 바뀐다. 

4. UI 비주얼 컴포넌트+텍스트

비주얼 컴포넌트: UGUI에서 그림을 실제로 그려준다. 

UI 텍스트 생성> 텍스트 컴포넌트는 텍스트로 들어온 값을 UI로 표시. 

외부에서 들어온 폰트 파일을 드래그&드롭으로 폰트 지정 가능. 폰트 사이즈 지정, 정렬 가능. 
Align by Geometry: 폰트를 정렬할 때 폰트의 형상을 기반으로 정렬. 선택 시 좀더 폰트의 모양에 맞춰 정렬. 
Horizontal Overflow: 글자가 글상자를 넘어갔을 때 어떻게 할 것인지 지정. (Wrap: 감싸서 자른다. Overflow: 가로방향으로 넘쳤을 때 넘치게 내버려둔다. 
Vertical Overflow: Truncate 지정 시 수직 방향으로 넘치면 자른다. Overflow 지정 시 내버려둔다. 
Best Fit 옵션: min 값, max 값 사이의 적당한 폰트 크기로 지정. 

Rich Text 선택 시 html 코드를 통해 텍스트에 포매팅 가능. 
Font Style: 사용하는 코드에서 지원하지 않는다면 정상적으로 표시되지 않을 수 있음. 
Line Spacing: 줄 간격
Material: 텍스트를 표시할 때 마테리얼을 통해서 컬러 표시 가능. 
Raycast Target: 모든 비주얼 컴포넌트들이 공통적으로 가지고 있음. 화면을 터치할 때 날아오는 광선에 타겟이 된다. (터치를 먹을 수 있다. ) 해제하면 터치를 먹지 않고 게임 오브젝트 뒤에 있는 물체가 대신 터치를 받을 수 있다. 

5. 이미지

UI>>이미지 컴포넌트 생성. 

이미지: 소스 이미지에 지정한 스프라이트 이미지 표시. 텍스처(3D 모델의 피부로 입혀주는 그림) 이 아닌 스프라이트(2D 게임에서 2D 이미지 평면을 나타내기 위한 이미지) 사용. 

2D 게임 모드일 때는 이미지들이 자동으로 스프라이트로 들어오지만 3D 게임 모드일 때는 이미지들이 텍스처로 들어옴
>>텍스처 타입을 디폴트가 아닌 스프라이트로 바꾸고 Apply. 
이미지 컴포넌트에 원하는 이미지를 Drag&Drop하면 컴포넌트에 이미지가 표시됨. 
이미지가 사이즈에 의해 왜곡될 수 있기 때문에 사이즈와 상관없이 비율을 유지하고 싶으면 Preserve Aspect를 선택. 

사실상 이미지가 UI의 모든 그래픽을 담당한다. 

이미지의 타입
-Simple
-Sliced: 들어오는 소스 이미지를 잘라서 쓰는 방식 사용. Sprite Editor에서 이미지를 9개의 영역으로 자를 수 있다.
		자른 부분 중 정중앙 부분은 잡아늘려 배치, 모서리 4부분은 잡아 늘리지 않고 사용, 양쪽 측면에 붙은 부분은 위아래/또는 양옆으로만 잡아늘리는 방식으로 사용
		>왜곡 없이 배치되어 다양한 사이즈에 대응 가능. 

		UI에서 어떤 창을 만들 때 사이즈별로 창 이미지를 준비하는 것이 아니라 하나의 프레임 이미지를 준비하고 해당 프레임 이미지의 모서리 부분들을 잘라서 지정해주면 됨. 
-Tiled: 이미지를 반복 배치하는 방법. Tiled에서도 모서리를 잘라줄 수 있다.(하지만 중간 부분이 잡아늘려져 배치되는 것이 아니고 여러개 반복되어 배치된다. )
-Filled: 채우는 방식. 슬라이스를 구현할 때 사용된다. 360도 반복하면서 채우는 방식이므로 Fill Amount를 줄이면 반시계(또는 지정한) 방향으로 이미지가 지워지고 늘리면 시계방향(또는 지정한 방향)으로 칠해진다. 
			Radial 360도 뿐만 아니라 Horizontal, Vertical 등 가로방향이나 세로방향으로도 채울 수 있다. 

이미지 컴포넌트도 마테리얼을 가지고 있다. 특수효과를 위해 사용하고 일반적인 UI를 만들 때는 잘 쓰지 않는다. 

6. raw 이미지

UI 요소들이 배치될 때 같은 선상에서 배치된다면 hierachy에서 가장 밑에 있는 요소가 가장 바깥쪽으로 그려진다(다른 UI 요소가 덮일 수 있음)

UI>>raw 이미지 생성. 이미지와 마찬가지로 그림을 그려주는 컴포넌트인데 입력으로 스프라이트가 아닌 텍스처를 받는다. 
		스프라이트와 달리 테두리를 지정할 수 없어 잘 사용하지 않는다. UV Rect가 있어 텍스처의 타일 설정이 가능하다. 

7. 마스크

UI 오브젝트가 다른 UI 오브젝트(ex: 텍스트) 를 자식으로 가질 때 자식 오브젝트가 부모 오브젝트의 범위를 벗어난다면 >> 마스크 사용. 자신의 영역 밖으로 나간 UI 그래픽을 자른다. 

Show Mask Grapic: 자기 자신도 같이 표시할지 하지 않을것인지 결정 가능. (해제하면 부모 오브젝트는 보이지 않는다. )

마스크: 그래픽을 통해 잘라낸다. (이미지 컴포넌트의 그래픽 안쪽에 있는 부분만을 남기고 잘라낸다) >>이미지 컴포넌트가 없으면 마스크가 동작하지 않는다. 

add component>>rect Mask를 사용하면 그래픽이 없어도 지울 수 있다. (rect Mask는 기본적으로 rect transform의 크기를 기반으로 잘라냄>> 별다른 필드값이 없고 무조건 사각형 범위로만 자르며 성능이 좋다. 

8. 그림자+외곽선

UI 오브젝트에 add component> Shadow를 선택하면 그림자가 생긴다. (색깔, 거리 지정 가능)

add component>> outline을 선택하면 테두리가 생긴다. (색깔, 두께 지정 가능) 

9. 비주얼 컴포넌트 정리

앞에서 나온 것들이 유니티에서 비주얼을 담당하는 컴포넌트들. 

유니티 UGUI에서 모든 그래픽(CG적인 모든 그래픽) 은 해당 컴포넌트들로 나타낼 수 있다. 
그리고 이러한 컴포넌트들을 제어하는 방식으로 그래픽을 표시하는 다른 UI 컴포넌트들이 있다. (직접적으로 그래픽을 표시하지는 않지만 해당 게임 오브젝트의 자식으로 그래픽을 표시하는 이미지 컴포넌트들이 붙은 게임 오브젝트가 있음. )

10. 인터렉션 컴포넌트+Selectable

인터렉션 컴포넌트: 마우스나 터치에 대해서 발생하는 이벤트, 키보드나 게임기 컨트롤러의 인터렉션까지도 감지해서 알맞게 대응 가능. )
ex) UI 버튼

모든 인터렉션 컴포넌트들은 Selectable이라는 베이스 클래스를 상속받아 만들어짐. >> 공통적으로 Selectable 베이스가 제공하는 기능들을 가지고 있음. 

셀렉터블 베이스 클래스를 상속받으면 Interactable, Transition, Navigation이라는 필드가 존재. (Button, Slider 등이 해당...) 

Selectable을 상속받은 인터랙션 컴포넌트들은 클릭을 했을 때 피드백이 온다. (클릭, 마우스 오버 시 색깔이 변하는 등) 

Navigation 필드에 Visualize 체크박스 체크 시 화살표 생성(여러개의 Selectable 상속받은 인터렉션 컴포넌트 중 하나를 선택 가능한데, 화살표는 선택이 넘어가는 순서임. )

Selectable을 상속받은 UI 게임 오브젝트들은 이벤트 시스템에 의해 선택 가능하게 된다. 이벤트시스템에 Selectable한 게임 오브젝트를 넣으면 정상적으로 동작한다. 

이벤트 시스템의 First Select:  게임이 시작되었을 때 자동으로 선택되는 컴포넌트 지정. 

필드값 Interactable: 체크 해제 되어있을 시 동작하지 않는다. 

Transition: 인터랙션 가능한 컴포넌트들이 유저가 터치, 클릭 등 이벤트 발생시켰을 시 어떻게 피드백 효과를 보여주느냐? (시각적 피드백) 
	ㄴex) Color tint> 색깔 변화.  Sprite Swap: 이미지 스프라이트 바꾸기

11. 버튼

UI>>버튼 추가 

인터랙션 컴포넌트들은 스스로는 그래픽을 그리지 않음. 
버튼 컴포넌트의 그래픽은 이미지 컴포넌트가 그리고 있고 버튼 안의 텍스트도 텍스트 컴포넌트가 그리고 있다. 

UI 버튼 게임 오브젝트는 Onclick 이라는 유니티 이벤트에 할당된 함수들을 클릭, 터치 당했을 때 자동으로 실행시키는 컴포넌트. 

3D 오브젝트 큐브의 색을 바꾸는 버튼 만들기
>>큐브에 스크립트 추가(Color change)

public class ColorChange: MonoBehaviour{

	public void ChangeColor(){
		GetComponent<Renderer>().material.color=Random.ColorHSV}
}

버튼의 Onclick 슬롯에 큐브를 드래그&드롭 하고 이벤트에 등록할 함수(ChangeColor)를 고른다. >>버튼을 누르면 큐브의 색깔이 랜덤하게 바뀜. 

Onclick 슬롯에 통제하고 싶은 오브젝트를 추가해 해당 오브젝트에 붙어있는 public 함수를 사용할 수 있다. 

버튼의 기본 색, 마우스 오버 시의 색, 클릭 시의 색, 인터렉션 불가능한 상태에서의 색을 지정할 수 있다. 

12. 토글

토클: 껐다 켰다 할 수 있는 체크박스를 만든다. 

UI>>토글 생성. 
버튼과 마찬가지로 스스로 그래픽을 표현하지는 않는다. (하위에 있는 Background, Label이 그래픽을 그림. )

토글 컴포넌트: 토글을 껐다 켰다 했을 때 어떤 일이 일어날지 결정 가능. 

토클 체크박스가 체크되었는지 안 되었는지 확인 가능(toggle-confirmed), OnValueChanged 유니티 이벤트를 통해 체크 or 체크 안했을 시 자동으로 어떤 함수가 실행되게 할 수 있음. 

public class ColorChange: MonoBehaviour{

	public void ChangeColor(bool isOn){ >>불리언 입력을 받는 함수. 
		
		if(isOn){
			GetComponent<Renderer>().material.color=Random.ColorHSV();}

		else{
			GetComponent<Renderer>().material.color=Color.white;}

}

ㄴOnValueChanged에 슬롯 추가> 큐브를 드래그&드롭으로 슬롯에 추가 >> 큐브가 가진 모든 컴포넌트들의 모든 public 함수 등록 가능. 

Static Parameters: 유니티 이벤트가 입력값을 전달하지 않고 우리가 직접 입력값 설정. 
Dynamic Boolean: 유니티 이벤트가 직접 입력값 전달 가능. 

13. 토글 그룹

체크박스 사용 시 여러 개의 체크박스 중 하나만 체크되어야 할 때가 있음. (라디오 버튼)
토글 그룹> 하나의 체크박스가 체크되면 나머지 체크박스가 해제되는 기능. 

UI>>패널 추가. (이미지 컴포넌트를 가진 게임 오브젝트) 
패널 안에 여러개의 토글을 배치하고 패널 안에 add component>> 토글 그룹. 토글 그룹 추가 시 토글들은 자신이 어디에 속했는지 그룹을 지정할 수 있음. 
같은 그룹에 속해 있는 토글끼리는 동시에 두 개 이상 체크 활성화 할 수 없다. 

토글 그룹의 Allow Switch Off>> 그룹 내의 어느 토글도 체크하지 않는 것이 가능하다. 

14. 슬라이더

유저가 핸들을 조정해서 어떠한 값을 코드에 전달할 수 있고, 반대로 프로그래머가 코드에 있는 값을 슬라이더에 전달해 슬라이더가 값에 맞춰서 자동으로 채워지거나 줄어들 수 있음. 
슬라이더 컴포넌트는 그래픽을 그리지 않지만 그래픽을 그리는 요소들의 크기를 통제. (Fill Rect, Handle Rect) 

Whole Numbers 체크하면 값을 조정할 때 슬라이더 값이 정수 단위로 움직임.  
Direction: 채우는 방향을 조절. 

Interactable 체크 해제 시 플레이어가 임의로 핸들 조정할 수 없음. (프로그래머가 코드를 통해 통제) 

슬라이더의 자식들
Handle Slide Area: 핸들을 그려주는 역할, 핸들이 없어도 Interactable 상태에서는 유저가 임의로 조정 가능하긴 함. 
Background: 배경. 지워도 정상적으로 동작. 
Fill Area: 채우는 영역. 
Fill: Fill Area를 채우는 역할. 

OnValueChanged 이벤트: Slider의 Value값이 변경될 때마다 자동으로 실행. 
들어가 있는 함수가 입력값으로 숫자를 받는다면 실시간으로 Value값을 같이 넣어 실행시켜줌.
